# Public native Wiki and support assistant

The current `/#knowledge/` renderer supports anonymous browsing. Employee routes and archives retain authentication. Public conversations use exact `/public/wiki-assistant/*` endpoints, independent random session tokens, strict origin/body checks and no inherited employee identity. Sessions expire after 12 hours. Conversation/contact records are scheduled for removal after 30 days (startup, hourly and new-session cleanup). Visitor inbox reads are limited to the configured support organization.

The assistant initially provides public-document navigation, confirmed support requests and feedback. All 236 source articles remain available to browse, but migrated material is not automatically marked safe for generated technical advice. Without an enabled, configured model and exact approved source hashes, responses have `status: sources_only` or `needs_human`; no model call occurs. Internal Answer sources reviews enable/revoke source eligibility. Model-assisted responses display validated original quotations with native article links. A quotation check is not a semantic proof of a generated paraphrase, so unrestricted model paraphrases are not served.

Public requests return `OL-*` support references. They appear in the private Visitor requests tab; these are not Zoho ticket numbers and no customer email is sent. Feedback and source-bound knowledge candidates are independently reviewable. Candidate approval does not silently rewrite the public Wiki. Unsafe incidents remain on the human path for the conversation, including later follow-ups. Provider failure or budget exhaustion falls back to source navigation.

Optional model configuration (server only): `PUBLIC_WIKI_MODEL_ENABLED=true`, `PUBLIC_WIKI_API_KEY`, `PUBLIC_WIKI_MODEL_ID`, `PUBLIC_WIKI_MODEL_DAILY_LIMIT`. Default model calls are disabled. The daily call cap is an application request cap, not a dollar guarantee; do not enable a billed model until a specific budget and provider pricing/controls are approved. It does not inherit employee evidence-review credentials. Only approved public source excerpts and the visitor's own question context are sent to the provider.

Internal support now preserves exact incoming/sent thread evidence, saved original/final versions, correction reasons and human-reported outcomes. Unknown reply-thread parents require an explicit human pairing confirmation. Known mismatches cannot be overridden. Rule-based findings explicitly do not prove factual correctness. Structured handovers bind the ticket source hash, authorized owner/receiver and acceptance status. Old revisions remain intact.

The internal Shopify adapter is read-only and inactive until a verified store application is configured. Use exact `SHOPIFY_SHOP_DOMAIN`, and either `SHOPIFY_CLIENT_ID` plus `SHOPIFY_CLIENT_SECRET` (client credentials), or an existing specifically authorized `SHOPIFY_ACCESS_TOKEN`. It performs a fixed 2026-10 GraphQL order query and exact order-number matching; it does not return customer addresses, email or payment data. Each fulfillment is shown independently. Carrier delivery is not customer receipt confirmation. No public order lookup is exposed. Store developer access is currently deferred by the user.

The existing single Mac support snapshot publisher must be restarted after deployment to export incoming thread identifiers. Keep the underlying poller, Bot callback, dispatcher and shared bridge intact. No new dispatch is implied by the restart.
